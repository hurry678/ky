## 中心论点

> Agent 记忆的遗忘在部署条件下失效——参数侧的软抑制经**量化塌回**，记忆侧的**逻辑删除**留在存储里。可靠的补救是把删除下沉到**密码层**，并把密钥交给用户。

写进结论与讨论，**不写成创新点**（国内评审易判"缺方法创新"）。

---

## 1. 两个创新点

### 创新点 1 · 残留攻击与再度量

基线是已发表 SOTA（SBU、MemSecBench），不是自建的假想系统。这一点决定了相关工作和对比实验能自己写出来。

| | 攻击 | 打什么 |
|---|---|---|
| a | 共享派生工件按设计存活 | SBU 形式化后置条件与 refcount 实现自相矛盾 |
| b | 索引陈旧窗口 `τ=100` + embedding 反演 | 删了明文没删向量 |
| c | 存储层残留 | 黑名单只是检索边界过滤 |
| d | 部署变换恢复（量化 / benign relearning） | 参数侧的软抑制 |
| e | 用 IAM 重测 SBU 的隐私声明 | 质疑度量工具，不是找实现漏洞 |

### 创新点 2 · Verified Forgetting 的密码学实例化

差异化落在**执行**而非**验证**：现有工作（TEE 见证 / ZK 证明 / 行为探针）都在事后验证平台是否遗忘，数据主体始终被动。

1. **2-of-2 秘密共享**：平台单独持份无法解密
2. **用户侧可穿刺 GGM 种子**：删除 = 用户单方面穿刺，不需相信平台
3. provenance 图驱动穿刺集合，**原子失效** embedding（不等 τ 阈值）
4. 删除定义从 Garg-Goldwasser-Vasudevan（Eurocrypt 2020）改写
5. 哈希链承诺仅做**问责层**，不承担"证明删除"

### ~~G1 · "安全理论"能否单独满足学位论文要求？~~ → 已由本人决定

**2026-09-09：路线 A 锁定。** 学生本人要求保留密码成分，故无论学院是否允许纯安全路线，创新点 2 均保留。G1 从决策门降为**确认项**——邮件仍应发（防学院有额外形式要求），但不再决定方向。净工期按路线 A 的约 15 个月计，须执行核心 / 压缩 / stretch 三档切分。

**由此产生的重心变化**：创新点 2 成为承重墙，其风险不是可行性（几百行必然跑通）而是**学术分量**。答辩必问"加密删除不是工业标准做法吗"，挡这一问靠四点：provenance 驱动的密钥作用域、索引原子失效、用户持份、**形式化删除定义**。前三条是设计，只有第四条是理论——**对信安学位论文，被当作"安全理论成分"看的正是第四条**。缺了它，创新点 2 就是"用了 Shamir 和一棵 GGM 树"，是工程不是理论。

故 **Garg-Goldwasser-Vasudevan 的形式化从第 4 优先级升为创新点 2 的关键路径**，优先于 8B（E12）与 ada-002 对齐。

### G2 · KL-to-random 的塌缩是规模问题还是方法问题？

rung0 = Qwen2.5-0.5B、rung1 = Qwen2.5-1.5B，**均全参 + Adafactor**（本机 12GB 可跑，1.5B 峰值实测 10.4G）。

**已判定（2026-09-09）：方法问题，不是规模问题。** 34 配置全败，且"效用先坏于遗忘"的签名说明目标函数本身不可分离（详见 E10）。

**推论**：攻击 d 的 SBU 专属命题**无法测试**——不是因为我的实现，而是因为公开发表的方法没有可用配置。这本身是对 SBU 的实质可复现性结论：它声称关键的 entropy fallback 只在从未公开的 supplementary 中（见 E3）。

**保留的范围限定**：8B 未测，而 SBU 用的是 8B，且规模趋势有利。故结论表述为"≤1.5B 上不存在可用窗口"，8B 列为 E12 待验。rung2 从"决定性实验"降为"收窄结论用"。

## 6. 表述纪律

三条"不得"，都是已经踩过或差点踩到的坑：

1. **mem0 的 history 明文不得写成"漏洞"或走负责任披露** —— 它是文档化特性。正确表述是删除语义与清除能力之间的设计缺口（见 E7）。
2. **不得表述为"提出可验证记忆治理框架"** —— `VMG` 与 `Verified Forgetting` 之名已被 arXiv 2604.16548 占，须表述为"其密码学实例化"。
3. **"划密码学保证的边界"是中心论点，放结论与讨论，不得写成创新点** —— 否则易被评为缺方法创新。

4. **攻击 b 不得单独陈述，必须挂在 GGV 约束 (i) 上。** 单说"删了明文没删向量会泄露"，会被"加高斯噪声/量化 embedding 就行了"顶回去——这两种防御已被复现为有效且不损检索。**能推出密码删除的是 GGV 以内存状态为准这一点**：加噪的、被删记忆的 embedding 仍然是残留，且防御随攻击者变强而失效，密钥销毁不会。轴线仍是"让攻击变难"vs"让数据不在"。
5. **不得混淆两种量化。** embedding 量化是**防御**（挡反演，见 E4）；权重量化是**攻击**（恢复被遗忘知识，见 E5）。量化在本文两头都占，讨论章需显式区分，否则读者会认为自相矛盾。

外加一条对我判断的折扣：这两天最令人兴奋的两条（mem0 漏洞、量化打穿 SBU）正好是缩水的两条；撑住的是最枯燥的两条：逐篇核文献、把 vec2text 跑起来。**凡出现"这个发现比预想更有分量"的表述，先打折再采纳。**
